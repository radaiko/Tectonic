Overview What it is

Tectonic is a browser-based parametric CAD system aimed at what Onshape and Fusion 360 do for mechanical design: sketch a profile, constrain it, drive solids from it, and keep the whole history editable. Scope is CAD only — no CAM, no simulation, no generative design.

Nothing is stored

There is no database and no cloud. Open a .tectonic file or start a new document; everything lives in memory until you export. Closing the tab discards unsaved work.

Single user

No accounts, no sign-in, no collaboration layer. The application is the modeling environment and nothing else.

Real B-Rep, not meshes

Geometry runs through a Rust boundary-representation kernel compiled to WASM, with a TypeScript fallback kernel if WASM fails to load.

Parametric all the way down

An ordered feature tree with a roll bar, dependency graph, suppression and reorder. Dimensions accept equations and global parameters.

Getting started 4 steps

Tectonic runs from source. Full build details, including the Rust kernel, are in build.md.

Clone and install

Node.js 20 or newer. Everything else comes from npm.

$ git clone https://github.com/radaiko/Tectonic.git
$ cd Tectonic
$ npm install

Start the dev server

Vite serves the app at http://localhost:5173 with hot reload. 

$ npm run dev

Model something

Pick New on the start screen, draw a closed profile on a plane, add constraints and dimensions until the sketch is fully defined, then press E to extrude it. Open the command palette with CtrlP to reach any tool by name, or press F1 for the in-app shortcut reference.

Save your work

Nothing persists on its own. Export to .tectonic to keep the full parametric history, or to STEP, STL, DXF and the other formats below for downstream use. 

$ npm run build   # production bundle in dist/
$ npm test        # run the test suite

Browser support: latest two major versions of Chrome, Edge, Firefox and Safari.

Keyboard shortcuts F1 in app

The same reference the in-app overlay shows. Press F1 or ? at any time to bring it up without leaving the model.

Architecture 30 modules

Domain models are renderer-agnostic — no React and no three.js below src/domain/. Geometry always goes through the IKernel interface, so the backend swaps without touching callers.

Geometric kernel

Written in Rust, compiled to WASM with wasm-pack. 14,000+ lines across 30+ modules, 447 unit tests.

  • Math: Vec2, Vec3, Mat4, Quat, Plane
  • B-Rep: Vertex, Edge, Face, Body, HalfEdge, Shell, Surface, BoundingBox
  • Operations: extrude, revolve, sweep, loft, boolean, fillet, chamfer, shell
  • Mesh: ear-clipping and Delaunay triangulation, tessellation, simplify
  • 14 operations exported through wasm-bindgen with JSON I/O, falling back to the TypeScript StubKernel if WASM fails to load

Stack

  • TypeScript in strict mode, plus Rust for the kernel
  • React for UI, Canvas 2D for sketching
  • three.js for 3D, WebGPU with WebGL fallback
  • Vite for build, Vitest and cargo test for tests
  • Constraint solver is pure TypeScript, no WASM dependency

Rendering

The render loop is on-demand: frames are drawn only when something changes, so an idle viewport costs no GPU time. CtrlShiftD opens the developer overlay with renderer backend, FPS, triangle count and draw calls.
